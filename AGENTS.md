# Carbon8 Website — React Router v8 SSR marketing site for Carbon8 (community-first climate org).

This is a content/marketing system: Vite 8 + TS 5.9 strict + Tailwind v4 + shadcn `base-maia`. No backend. See [Architecture](docs/architecture.md), [Verification](docs/verification.md), [Workflow](docs/workflow.md).

## Verification (MUST)

- Run `make check` — must exit 0 before every commit. why: single consistent-state predicate.
- Never skip layers: L1 `npm run lint` + `npm run typecheck`, L2 `npm test`, L3 `npm run build`. Do not proceed to Layer N+1 if Layer N fails.
- Never set `feature_list.json` state to `passing` directly — run `make verify-feature F=<id>`. why: harness-gated pass state.

## Constraints (MUST / MUST NOT)

- MUST use `~/` for app imports (source: tsconfig + Vite alias).
- MUST NOT import across features; MUST NOT add barrel `index.ts` re-exports. why: tree-shaking + Bulletproof layers (source: FOLDER_STRUCTURE.md).
- MUST keep components/hooks pure; `npm run lint` with zero `react-hooks/*` disables except the two in CONSTRAINTS.md. why: Rules of React (source: CONSTRAINTS.md).
- MUST NOT invent stats, testimonials, partner logos; project status `concept`/`in_development` only. why: pre-launch honesty (source: FOLDER_STRUCTURE.md).
- MUST update docs in the same commit as code — no stale documentation.
- MUST keep one logical operation per commit; repo consistent after every commit.

## State

- Read `PROGRESS.md`, `DECISIONS.md`, `feature_list.json` at session start. WIP=1: only one `active` feature at a time (`make vcr` must stay 1.0).
- State machine: `not_started → active → passing`, no skipping. Each feature completable in one session or split it.

## Clock-in / Clock-out

- Clock-in: read `PROGRESS.md`, run `make check`, activate one feature.
- Clock-out: run `make clean-check`, update `PROGRESS.md` + `docs/quality-document.md`, run `make check`, commit with WHY message.
- If running low on context, do NOT rush — stop, update `PROGRESS.md`, commit a clean checkpoint.

## Definition of Done

Complete = runtime evidence passes (all layers, app ready state, side effects correct, no debug artifacts: `console.log`/`debugger`/`.only`), not code-written or confident.

## Boundaries / E2E

- `make check-arch` enforces `.harness/arch-rules.json` (WHAT/WHY/FIX). Every new review-caught error category becomes a rule there.
- Layer 3 e2e (build + startup smoke) required when changes cross component/domain boundaries.

## Observability / Clean-state

- Sprint contract before each feature (`templates/sprint-contract.md`); trace verification events; score against `templates/evaluator-rubric.md` (all dimensions ≥ B).
- Session complete only when `make clean-check` passes (build, tests, feature list, no debug artifacts, startup path). Immediate + weekly/monthly sweep cleanup.

## Repo facts

- Dev `npm run dev` (port 5173); prod `npm run build` + `npm run start` (Dockerfile: `node:24-alpine`).
- Routes in `app/routes.ts`; page files in `app/routes/` with types from `./+types/<name>` (regenerated by typecheck).
- TS strict + `verbatimModuleSyntax` + `noEmit`. Add UI via `npx shadcn add <component>`. VCS: git backend with `jj`.

## Tools

- opencode: permissions scoped in `opencode.json`; commands `/check`, `/verify-feature`, `/clean-check`. Skill: `.agents/skills/react-router` (React Router v8 SSR). No MCP servers by default.
- Hooks (`.opencode/plugins/harness.ts`, auto-loaded): clock-in trace on session start, block on hand-editing `feature_list.json` to `passing`, harness pointers re-injected on compaction.
